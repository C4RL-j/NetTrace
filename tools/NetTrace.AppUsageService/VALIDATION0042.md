## Cleanup and limits

The final worker confirmed SCM error 1060, no collector process, no exact owned
ETW session and no stale service pipe. Both lifetimes shut down cleanly. The
owned default database and companion files were removed, protected staging was
removed, and the pre-existing ProgramData directory/ACL remained intact. The
validation retained JSON evidence only. No permanent service or recovery policy
was installed, and the original App Usage 003 validation script was unchanged.

A forced kill may lose uncommitted usage, normally approximately the latest
five-second checkpoint window when storage is healthy. A storage outage can
extend that window. This phase does not claim zero-loss crash accounting.
Midnight and checkpoint-failure cases were deterministic tests; it did not
change the machine clock or force Windows sleep/shutdown.
