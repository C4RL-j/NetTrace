show no significant memory growth and no growing client handle count. Service
activity continued throughout, so its two extra handles cover the complete
live window. Focused repeated-read tests exercise connection/resource disposal

## Recovery, persistence and cleanup

A normal client observed `CollectorUnavailable`, applied the existing bounded
reconnect backoff and then reached `Connected` after the temporary service
restarted. It completed three Today reads successfully. A final client against
the removed service wrote its typed unavailable connection state and returned
the expected diagnostic exit code 1 without crashing.

The initial service lifetime committed six usage checkpoints, with zero failed
checkpoints and zero pending keys on clean stop. Accepted and committed bytes
matched exactly: download 82,555,292 and upload 1,549,004. The restarted lifetime
also completed its final checkpoint, with zero pending keys and non-degraded
persistence. Checkpoint timing, event acceptance and retention were unchanged.

Final cleanup reported SCM error 1060, no owned service process, no stale service
pipe and no exact owned NetTrace ETW session. The entire newly owned protected
run staging directory, including its isolated database and companions, was
removed. The real default database and existing ProgramData NetTrace parent ACL
were left untouched. No permanent service or startup policy was installed.

Controlled range, aggregation, sorting, empty history, bounded storage failure,
